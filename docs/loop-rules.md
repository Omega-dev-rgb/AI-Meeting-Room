# 自走ルール（ループエンジニアリング実験）

オーナーへの確認を最小にして、AIエージェントが「計画 → 実装 → テスト → 修正 → マージ」を回す。

## 1サイクルの流れ

1. `docs/backlog.md` から一番上の未着手タスクを取る（なければ仕様書から切り出して追記する）
2. ブランチを切って実装する。ロジックは `src/core` に置きテストを書く
3. `npm run typecheck && npm test && npm run export:web` を通す。画面変更はスクショで確認する
4. PR を作る。CI が緑なら自分でマージする（squash）
5. `docs/experiment-log.md` に1行記録し、次のタスクへ

## 確認なしで進めてよいこと

- コードの実装・修正・リファクタリング、テストの追加
- ブランチ・PR の作成、CI が緑の PR のマージ、Issue / バックログの整理
- 作業スレッドの分割、作業用プロンプトの作成
- 仕様の細部（文言、画面配置、既定値）の判断。判断理由は PR に書く

## 必ずオーナーに確認すること

- お金がかかること（有料サービス登録、API課金を伴う実験、有料プラン）
- 外部への公開（App Store / TestFlight 提出、X・note への投稿）
- ゴールや MVP の範囲を変えること
- 秘密情報（APIキー、トークン、アカウント）が必要なこと
- 取り消しが難しい操作（履歴の書き換え、データ削除）

確認は選択肢カードで1回にまとめ、推奨案を付ける。返事を待つ間も、確認に依存しない作業は進める。

## 止まったとき

- 同じ失敗で3回つまずいたら、別の方法を試すか、バックログの別タスクに移る
- 環境の制約（ネットワーク遮断など）は記録してから回避策を取る
